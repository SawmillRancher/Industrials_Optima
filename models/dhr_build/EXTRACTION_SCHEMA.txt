# Danaher (DHR) data extraction — schema & rules

## Sources (SEC EDGAR only — the Danaher IR website is blocked; its releases are the 8-K Ex. 99.1 exhibits)
- Text versions of every document are in $DHR_SRC/txt (one table row per line, cells joined by ` | `).
  DHR_SRC=/tmp/claude-0/-home-user-Industrials-Optima/02384087-e4da-5e3d-bb00-3762059a75d7/scratchpad/dhr_src
- `$DHR_SRC/period_index.json` maps each period key to: `release` (earnings release text), `filing` (10-Q, or 10-K for
  annual and Q4 periods), `next_release` / `next_filing` (the same documents one year later). File names embed the
  filing date, form and accession: `<date>_<form>_<accession>_<doc>.txt`. EDGAR URL of a document =
  https://www.sec.gov/Archives/edgar/data/313616/<accession without dashes>/<doc>.htm (older ones may be .htm/.txt —
  check `$DHR_SRC/filings.json` `primary` / `files`). Record those URLs in `sources`.
- Read the text with grep / sed / python. Files are large (10-K up to ~1 MB) — grep for the statement headings
  ("CONSOLIDATED STATEMENTS OF EARNINGS", "CONSOLIDATED BALANCE SHEETS", "CONSOLIDATED STATEMENTS OF CASH FLOWS",
  "SEGMENT", "Core sales", "Adjusted Diluted Net Earnings", "Free cash flow") and read the surrounding lines.
- TEXT QUIRK: the converter drops cells that are only ")" so negative numbers may appear as "(25,433" with no closing
  parenthesis. An opening parenthesis means negative. Em-dash "—" means zero.
- Optional cross-check: `$DHR_SRC/dhr_facts.json` is the XBRL companyfacts dump (2009+): us-gaap Revenues /
  SalesRevenueNet, OperatingIncomeLoss, NetIncomeLoss, Assets, NetCashProvidedByUsedInOperatingActivities…

## Basis rules
- Quarter records (Q1..Q4, 2013 onward): income statement, adjusted EPS bridge, core growth and FCF from that quarter's
  earnings release ("Three-Month Period Ended" columns), AS ORIGINALLY REPORTED. Q4 = the Q4 release's three-month
  column (only if the release lacks one, derive Q4 = FY − 9M from the 10-K and Q3 10-Q, and say so in `notes`).
  Segment sales / operating profit: from the release if it has a segment table, otherwise the 10-Q segment note
  (three-month columns); for Q4 derive FY (10-K) − 9M (Q3 10-Q) if not published and say so.
  Balance sheet = that quarter end (10-Q; Q4 = 10-K). Cash flow = YEAR-TO-DATE statement (10-Q; Q4 = 10-K full year);
  set `cf.ytd_months` to 3, 6, 9 or 12.
- Annual records (2006–2025): Q4 release twelve-month columns + that year's 10-K (as originally reported) for the full
  IS, BS, CF, segment note (sales, operating profit, D&A, capex, identifiable assets), debt note, employees.
- Prior-year comparatives (`py` section): ALSO extract the prior-year comparative column as presented in THIS period's
  documents (quarter: same quarter a year earlier, three-month column; annual: prior fiscal year) for the income
  statement, segment sales / operating profit and adjusted EPS. These are used to put the periods just before each
  spin-off (Fortive Jul-2016, Envista Dec-2019, Veralto Sep-2023) and other discontinued operations on the recast
  continuing-operations basis. Set `py.restated` = true if the comparative differs from what was originally reported
  for that period because of discontinued operations / segment recasts (say why in `py.notes`), else false.
- Units: USD millions to 1 decimal exactly as published (thousands → divide by 1,000, round to 1 decimal); shares in
  millions (thousands → /1,000, 3 dp); per-share in $ as published; percentages as numbers in percent (e.g. 3.5).
- Stock split: Danaher had a 2-for-1 split in June 2010. Record shares / EPS / DPS EXACTLY as published in the source and
  set `is.per_share_basis` to "pre_split" or "post_split". Do not adjust yourself.
- Signs: fields marked (positive) are positive numbers for costs; "signed" fields keep the sign of their effect on
  earnings / cash (income or inflow positive, expense or outflow negative).
- Use null when a figure is not published for that period. Never estimate. If you compute a value (sum / difference /
  FY − 9M), say so in `notes`. Every record must carry its source URLs.

## Clarifications (from the pilot)
- Null vs zero: a line that exists and shows "—" = 0.0; a line that is not presented at all = null. An absent row in a
  growth table (e.g. no acquisitions row for a segment) = 0.0.
- Annual records: when the release and the 10-K differ in labels or amounts, the 10-K wins.
- Spin-off / IPO cash: put separation-related financing lines that are not in the continuing financing subtotal
  (e.g. Envista IPO proceeds, "cash distributions to/from Envista/Fortive/Veralto, net") in `cf.spin_cash` (signed);
  use `cf.cff_disc` only for lines explicitly labelled discontinued operations.
- `cf.stock_iss`: proceeds from stock-based-compensation issuance only (may be a net negative). Public equity offerings
  (common or preferred) go in `cf.equity_offering` (positive; add the field) — preferred offerings may use `pref_iss`.
- Other non-cash operating lines not in the named fields (inventory step-up amortization, make-whole premiums, pension,
  etc.) stay in `lines_raw`; the model derives the remainder.
- `ngaap.item_amounts` location may also be "below_ni" (e.g. MCPS dividends / if-converted adjustments) or
  "discops".
- `seg.recurring_pct`: may be computed from a revenue note (say so). Add per-segment `core_ex_resp` if stated.
- `is.dps`: dividends declared per common share for the period (10-Q / 10-K equity note or release); say the source in notes.
- Fill segment `amort` / `dep` for quarters too whenever the 10-Q / release presents them.

## Self-checks before writing each period (re-read the source if they fail)
- is: gp − sga − rnd − Σ other_op_lines = op_profit; op_profit + Σ nonop − interest_exp + interest_inc = ebt;
  ebt − tax = cont_ops; cont_ops + disc_ops = net_income (±0.6; old releases in thousands round to 0.1).
- seg: Σ segment sales = is.sales; Σ segment op_profit + other_op_profit = is.op_profit (±1).
- ngaap: eps_bridge_start + Σ eps_bridge = adj_eps_pub (±0.01).
- cf sections: cfo + cfi + cff + fx = net_change; cash_begin + net_change = cash_end (±0.6).
- bs: ta = tle; components sum to subtotals (±1).
Report any check that does not pass (with the reason) in `notes`.
