## Sources (SEC EDGAR only — the Wabtec IR website is blocked; its releases are the 8-K Ex. 99.1 exhibits)
- `filings.csv` lists every 10-K, 10-Q and earnings 8-K (Item 2.02) since 2006 with its EDGAR folder URL. CIK 943452.
- List a folder's documents: `curl -sS -H "User-Agent: $UA" <folder_url>index.json` (JSON `directory.item[].name`).
  The earnings release is the exhibit named like `*ex991*`, `*ex99-1*`, `*pressrelease*`, `*991*`. Ignore .jpg slides unless told.
  Some quarters have TWO Item 2.02 8-Ks (e.g. a preliminary results / tax-reform note, then the full results release a few
  weeks later). ALWAYS use the full final results release that has the complete financial statements.
- UA: ALWAYS send header `User-Agent: Industrials Optima research research@industrialsoptima.dev` (SEC requires a UA;
  do NOT use any other email). Keep to <= 5 requests/second (add `sleep 0.3` between curls).
- Convert HTML to compact text (one table row per line, cells joined by ` | `):
  `python3 h2t.py file.htm > file.txt` — then read/grep the text. Save raw files under `src/<period>/`.
- Optional cross-check: `wab_facts.json` is the XBRL companyfacts dump (2009+), useful to verify GAAP totals
  (e.g. us-gaap:Revenues / SalesRevenueNet, NetIncomeLoss, Assets, NetCashProvidedByUsedInOperatingActivities).

## Basis rules
- Quarterly periods (Q1..Q4): IS / segment / non-GAAP from that quarter's earnings release ("Three Months Ended" /
  "Fourth Quarter" columns), AS ORIGINALLY REPORTED. Q4 = the Q4 release's three-month column (do NOT derive Q4 = FY − 9M
  unless the release lacks a Q4 column; if derived, say so in `notes`).
- Quarter records ALSO need `cf` (year-to-date cash flow as of that quarter end, from that quarter's 10-Q; for Q4 use the 10-K
  full-year) and `bs` (balance sheet at that quarter end, from that 10-Q / 10-K). Set `cf.ytd_months` to 3, 6, 9 or 12.
- Annual periods (FY): Q4 release twelve-month columns plus the 10-K for everything else (full cash flow, full balance sheet,
  segment D&A / capex, product-line sales, employees, dividends). FY2006–FY2012 use that year's 10-K (as originally reported)
  and its Q4 release.
- Units: USD millions to 1 decimal exactly as published (thousands → divide by 1,000 and round to 1 decimal); backlog in USD m;
  shares in millions (thousands → /1,000, 2 dp); per-share in $ as published.
- Stock split: Wabtec did a 2-for-1 split in June 2013. Record shares / EPS / DPS EXACTLY as published in the source and set
  `is.per_share_basis` to "pre_split" or "post_split". Do not adjust yourself.
- Signs: costs/expenses as POSITIVE numbers where the field says "(positive)"; "signed" fields keep the sign of their effect on
  earnings / cash (income or inflow positive, expense or outflow negative).
- Use `null` when a figure is not published in the source for that period. Never estimate, never back-solve silently.
  If you compute a value (e.g. a sum of sub-lines or a difference), add a short note in `notes`.
- Every record must carry the source URLs used.

## Output
One JSON file per period in `data/` named `<period_key>.json`, period_key like `2012`, `Q1-13`, `Q4-25`, `Q2-26`.
Quarter records: sections `seg`, `is`, `ngaap`, `cf`, `bs`. Annual records: `seg`, `is`, `ngaap`, `cf`, `bs`, `extra`.

## Self-checks before you finish each period (fix extraction errors, re-read the source)
- seg: frt_rev + trn_rev = is.net_sales (±0.5); frt_op + trn_op + corp_op = is.op_income (±0.5);
  Σ frt_pl = frt_rev and Σ trn_pl = trn_rev where published (±1)
- is: gp − sga − eng − amort − Σother_op_lines = op_income; op_income − interest + other_inc = ebt; ebt − tax = cont_ops;
  cont_ops + disc_ops = net_income; net_income − nci = ni_wab (±0.5 each; releases round to $m from 2019)
- ngaap: Reported row + Σ item rows = Adjusted row in each column (±1); ebitda_op + ebitda_other + ebitda_dda = ebitda_pub (±1)
- cf sections sum to cfo / cfi / cff; cfo + cfi + cff + fx = net_change; cash_begin + net_change = cash_end
- bs: total assets = total liabilities + total equity (± any mezzanine / redeemable NCI — note it); components sum to subtotals
Report any check you could not make pass (with the reason) in `notes`.
